TRUST404 · TRACK 3 · BEFORE EXECUTION

BlockNotice

거절된 출금은 트랜잭션이 되지 않습니다.
그래서 기록이 기관 쪽에만 남습니다.

오프체인 출금 판단의 서명 영수증을 요청자에게 돌려주고,
기관이 서명한 약속이 지켜졌는지를 기관 서버 없이 확인합니다.

저장소: github.com/kimsabin725/blocknotice · 모든 수치는 npm run demo 한 명령으로 재현됩니다

1

문제 정의

승인은 체인에 남고, 거절은 아무 데도 안 남는다

출금이 승인되면 트랜잭션이 남습니다. 누구나 봅니다.

출금이 거절·보류되면 기관의 내부 DB 말고는 어디에도 안 남습니다.

나중에 기관이 「그런 요청 없었다」거나 「사유는 이랬다」고 말을 바꾸면, 이용자에게는 반박할 근거가 없습니다.

가상자산이용자보호법은 기록·통지 의무를 만들었지만, 그 기록이 지켜졌는지 제3자가 확인할 형식은 비어 있습니다.

실행 전(before execution)에 일어나는 보안 문제

체인에 실행 결과가 남기 전, 「누가 언제 무엇을 판단했는가」가 한쪽에만 있습니다.

이건 암호학 문제가 아니라 증거 비대칭 문제입니다. 기관은 다 알고, 이용자는 아무것도 증명 못 합니다.

BlockNotice가 하는 일: 그 비대칭을 서명 영수증 + 공개 커밋으로 대칭에 가깝게 만듭니다.

2

누구를 위한 것인가 — 먼저 좁힙니다

1차 장면은 기관 커스터디입니다

닿는 사람

기관 고객. 이미 외부 지갑·HSM으로 서명하고, 커스터디 계약에 SLA가 있어 증빙을 계약으로 요구할 힘이 있습니다.

출금 주소에 서명할 수 있는 외부 지갑 보유자.

조건부

거래소 앱 내부 이용자는 passkey가 거래소 밖(단말·OS)에 있을 때만. 거래소가 키를 대신 보관하면 보증은 전부 무효입니다.

안 닿는 사람

국내 거래소 이용자 대부분. 커스터디얼이라 키가 없습니다.

이들에게 닿으려면 거래소 밖 키가 먼저입니다. 그 전엔 남는 경로가 소송뿐입니다.

이걸 첫 장에 두는 이유 — 「모든 이용자를 위한 것」이라고 말하면 가장 먼저 무너지는 곳이 여기입니다.

4

어떻게

서명 영수증 + 컨트랙트가 직접 계산하는 공개 로그

요청자 ──서명 요청(EIP-712)+HPKE 봉투──▶ 기관 ◀── AcceptedReceipt ────────────── (기록 기한 + 요청자 바인딩, REQ 리프 기록 기관 서명) ◀── DecisionRecord ────────────── (암호화 전달, 기관 서명) DEC 리프 기록 공개 로그 : append-only 머클 트리(깊이 32) 루트는 제출받지 않고 컨트랙트가 계산 검증기 : 파일 + 공개 로그 루트만으로 판정 기관 접속 0회 (실측)
  • 루트를 제출받지 않습니다. 리프를 받아 컨트랙트가 계산합니다. 기관이 자기가 만들지 않은 트리의 루트를 올릴 수 없습니다.
  • 기한은 기관의 시계가 아니라 체인이 본 블록에서. 영수증이 인용한 앵커의 실제 블록 + 등록된 간격을 컨트랙트가 다시 계산해 대조합니다.
  • 영수증 사본은 자격이 아닙니다. 이름이 적힌 요청자만 챌린지를 열 수 있고, 그 바인딩에 기관이 서명합니다.
  • 컨트랙트는 해시만 저장합니다. 요청 내용·통지문·사유를 모릅니다.
5

보증하는 것 / 보증하지 않는 것

「모르겠다」와 「위반이다」를 섞지 않습니다

보증합니다

  • 기록 무결성 — 영수증 서명과 공개 커밋의 일치. 사후 교체 탐지.
  • 접수 책임 — 서명한 기록 기한이 지켜졌는가.
  • 독립 제출 — 영수증 없이도 공개 경로에 제출 사실을 남김.
  • 기관 접속 0회 — 검증 중 나간 HTTP 호출을 세어서 보고. 상수가 아니라 실측.

보증하지 않습니다

  • 비공개 사유의 진실성 — 커밋은 교체를 탐지할 뿐.
  • 기관이 아무에게도 안 알린 판단 — 존재를 발견 못 함.
  • 오프체인 전달 — 어떤 컨트랙트도 증명 못 함. 영수증 없는 공개 제출은 중립 기록.
  • 완전성 — 각자 자기 항목만. 전체는 근사.
  • 법적 강제력 — 체인은 의무를 만들지 않음.

판정 5분류: CONFIRMED · NOT_DUE · OBLIGATION_UNMET · UNVERIFIABLE · OUT_OF_SCOPE — 「아직」과 「모름」은 위반이 아닙니다.

무엇이 새로운가 — 정직한 델타

「Arbitrum delayed inbox와 뭐가 다르죠?」

발명이 아니라 이식입니다. 롤업은 프로토콜이 포함을 강제합니다. 오프체인 결정 서비스에는 그 강제가 없습니다.

  • 포함 여부를 롤업 상태 대신 머클 앵커로 판정합니다.
  • 강제가 없는 자리를 「기관이 서명한 기한」 + 「체인이 본 앵커에서의 역산」으로 채웠습니다.
  • CT(RFC 6962)와 달리 여기선 안 올리는 게 이득이라, 안 올린 사실을 요청자가 자기 영수증으로 증명하게 만들었습니다.

기술 델타는 하나입니다

나머지 셋 — 2단 사유 공개(약관 번호 평문 + 세부 커밋), 분류표 기반 판정 상한, ACK 내장 — 은 규제 매핑입니다.

독창성이 아니라 문제 정의·확장성 쪽에 놓습니다.

한계 — 우리가 먼저 적습니다

안 되는 것, 안 만든 것

  • 요청자 = 결정자는 못 잡습니다. 자기 지갑·같은 법인.
  • 영수증 보류는 못 막습니다. 성실히 앵커하며 영수증만 안 주면 위반 0건. 수수료 세금으로 퇴화할 뿐입니다.
  • 경제적 강제층(stake·fee)은 설계만. 지금 컨트랙트엔 예치금도 수수료도 없습니다.
  • serviceId는 선착순. 남의 영수증 위조는 불가하지만 이름은 뺏깁니다.
  • 앵커키 보유자의 역사 분기 — consistency proof 온체인 검증 미구현. 2-of-3 멀티시그 권고.
  • 에폭 size 증가분이 건수를 흘립니다.
  • 키 회전 미구현. 요청자 키 분실 = 자기 증거 상실.
  • 서명된 타임라인은 양날. 기관 방어 증거이자 소송의 원고 증거. 법무팀이 거부할 수 있습니다 — 기술로 못 풉니다.

인접 블록 재조직으로 판정이 뒤집힐 수 있어 검증기는 확정된 앵커만 씁니다. 컨트랙트는 이걸 막지 못합니다.
